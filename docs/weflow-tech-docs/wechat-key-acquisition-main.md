# 密钥获取机制总览

做微信本地数据解析时，先把“密钥”分成两类：

1. 数据库密钥：用于打开加密数据库（如 `message_*.db`）。
2. 图片密钥：用于解密聊天图片 `.dat`（`xorKey + aesKey`）。

这两类密钥来源不同，不要混用。

## 1. 统一流程

推荐按下面顺序执行：

1. 先拿数据库密钥，确认数据库可正常读取。
2. 再拿图片密钥，优先走 `kvcomm -> code -> 公式推导 -> 样本验真`。
3. 若推导失败，再走内存扫描兜底。

## 2. 三端核心差异

1. Windows：自动化程度最高，数据库与图片都可直接走本地流程，失败后可内存兜底。
2. macOS：受系统安全策略影响明显，进程级扫描常需要管理员授权与调试权限。
3. Linux：本地提取较直接，但进程内存扫描通常需要更高权限（常见为 `sudo`）。

## 3. 图片密钥的关键点

图片解密不是只要一个值，而是两把钥匙：

1. `xorKey = code & 0xFF`
2. `aesKey = MD5(String(code) + cleanedWxid).substring(0, 16)`

其中 `code` 来自 `kvcomm` 文件名，`wxid` 需要按规则清洗（如 `wxid_xxx_yyyy -> wxid_xxx`）。

## 4. 为什么必须验真

密钥计算后要做样本验真，否则非常容易“算出一组错密钥还以为成功”。

验真方式：

1. 取一份 V2 图片样本的 `0x0F..0x1F` 16 字节密文。
2. 用候选 `aesKey` 做 AES-128-ECB 解密。
3. 命中 JPG/PNG/WEBP/WXGF/GIF 头才算通过。

## 5. 常见失败原因

1. 用错账号目录，导致 `wxid` 不匹配。
2. `kvcomm` 没有有效 `code` 文件（缓存过少或目录选错）。
3. `wxid` 没做清洗，AES 计算错误。
4. 把 V1/V2/V3 混为一种算法。
5. 无验真直接批量解密，结果全部损坏。

## 6. 阅读顺序

1. 先读各系统文章（`03-01/03-02/03-03`）确定你的平台操作步骤。
2. 再读 `03-04`，按用户流程拿到可用 `xorKey/aesKey`。
