# macOS：数据库密钥挂点定位机制

当前采用锚点 + 语义 + 严格校验的定位机制，由于Mac端特性，其无法采用字符串定位

## 1. 模块与范围选择

### 1.1 优先主可执行映射

优先选择主二进制范围（`/Contents/MacOS/WeChat`），避免误扫 framework/helper/dylib。

### 1.2 新版本补充策略

当微信版本大于4.1.8的时候，主模块从/Contents/MacOS/WeChat变成了framework中的wechat.dylib，所以需要优先考虑wechat.dylib，旧版本则直接匹配Wechat模块

## 2. 锚点与候选生成

找到锚点字节：

`mov x3, x2; mov x2, x1`

对应字节序列：

`E3 03 02 AA E2 03 01 AA`

命中锚点后，候选地址定义为：

`candidate = anchor - 0x10`

## 3. 候选语义判定

候选要满足严格 ARM64 形态：

1. `ADRP`
2. `LDR (imm64)`
3. `CBZ`
4. `BR`
5. `mov x3, x2`
6. `mov x2, x1`

并且在前 `0x80` 字节内必须存在无条件 `B` 跳转。

## 4. 严格收敛

通过前面的还不够，必须再验证其分支目标是否命中 DB sink 形态：

1. `ADRP + LDR + CBZ + BR`
2. 紧跟 `cbz x0`
3. `cbz x2`
4. `cbz w3`

只有通过这层校验，才能作为最终的选择

## 5. 命中后如何确认是最终数据库密钥

断点命中后不会直接把当前数据当最终结果，而是继续做一次参数过滤：

1. 先确认命中线程 PC 在 `target` 或 `target + 4`。
2. 读取寄存器参数（arm64 下看 `x1`、`x2`）。
3. 只接受 `x1 != 0 && x2 == 32` 的调用。

其中：

1. `x1` 代表 key 指针地址。
2. `x2` 代表 key 长度。

只有长度正好 `32` 才视为最终数据库密钥调用。  
其他长度（例如 99，这是派生后子密钥的长度，并非主密钥）会被跳过，并重新挂断点继续等待下一次命中。

在参数满足后，才会执行：

1. 从 `x1` 指向地址读取 32 字节。
2. 转十六进制字符串输出。

因此 macOS 侧判定标准不是“断点触发就成功”，而是“断点触发 + 参数长度=32 + 可读出32字节”。
